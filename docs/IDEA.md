# Голосовой ассистент регистратуры: идея решения

Хакатон «Точка сборки», кейс DBI «В часы пик не дозвониться».

## Проблема в цифрах

Цифры посчитаны по данным кейса: журнал звонков за 92 дня (17 772 звонка) и история записей
за 6 месяцев (35 470 записей).

| Показатель | Легенда кейса | Данные кейса | Цель |
|---|---|---|---|
| Звонков в день | до 200 | 193 | — |
| Пропущенные звонки, в среднем | 30–40% в пик | 20,7% | ≤ 15% |
| Пропущенные в часы пик (7–10, 16–18) | 30–40% | 24,9% | ≤ 15% |
| Звонки до 8:00 и после 20:00 | — | пропущены на 100% (712 звонков, 4%) | 0% |
| Неявки на приём | 18–25% | 13,1% (26 в день) | ≤ 12% |
| Средний отвеченный разговор | 4–5 мин | 2,0 мин | ≤ 2,5 мин у ассистента |
| Результат отвеченных звонков | — | записан 54%, справка 35%, перевод 11% | ≥ 60% без человека |

Вывод: 89% отвеченных звонков — запись или справка, то есть типовые операции. А на ранние
утренние и вечерние звонки сейчас не отвечает никто.

## Идея

**Ассистент работает рядом с регистратором, а не вместо него.** Он берёт на себя типовые
звонки и обзвон с напоминаниями. Всё нестандартное, медицинское и конфликтное сразу уходит живому
сотруднику вместе с карточкой, чтобы пациенту не пришлось повторять.

Пять принципов:

1. **Безопасность раньше сценария.** Каждая реплика пациента сначала проходит проверку на красные
   флаги из регламента («давит в груди», «не может дышать», «отошли воды»…). Если флаг сработал,
   разговор о записи прекращается: ассистент говорит про 103/112 и переводит звонок с приоритетом P1.
   Ложная тревога допустима, пропуск — нет.
2. **Решения принимает код, а не нейросеть.** Цель звонка, специальность, даты, ФИО и даты рождения
   («двенадцатое марта семьдесят восьмого») разбирают правила. Записывает, переносит и отменяет
   детерминированный код по правилам МИС. LLM (Claude) подключается только к репликам, которые правила
   не поняли. Она лишь переписывает фразу в каноническую форму и никогда не говорит с пациентом сама.
3. **Каждое действие оставляет след в МИС.** Запись, перенос и отмена идут через API стенда, перевод
   и вызов на дом фиксируются заявкой в `/escalations`. Повторного ручного ввода нет: жюри видит
   результат в админке.
4. **Разговор проще и быстрее, чем с оператором.** Никаких «нажмите 1». В одной реплике не больше
   трёх вариантов, время произносится словами («в девять тридцать»), ключевые данные повторяются для
   подтверждения. По просьбе «соедините с человеком» ассистент соединяет сразу, без уговоров.
5. **Персональные данные остаются в контуре.** Распознавание и синтез речи — локальные модели.
   В LLM не уходят шаги с ФИО, адресом и описанием состояния, а телефоны и даты маскируются.
   Если пациент против записи разговора, реплики не сохраняются.

## Как это работает

```
Звонок ─► STT (локально) ─► ┌──────────────────────────────────────────────┐
                            │ 1. Красные флаги        → 103/112 + перевод P1 │
                            │ 2. Маршрутизация R-02…  → оператор, жалоба,    │
                            │                           платное, стоматология│
                            │ 3. Медицинский вопрос   → граничная фраза      │
                            │ 4. Сценарий (правила)   → запись / перенос /   │
                            │    └ не понял → Claude    отмена / справка /   │
                            │      переписывает фразу   вызов на дом         │
                            └───────┬──────────────────────┬───────────────┘
                                    ▼                      ▼
                     Стенд «Регистратура» (МИС)    Расписание из Excel
                     клиенты, записи, заявки        − записи команды = свободные слоты
                                    │
TTS (локально) ◄── ответ ◄──────────┘
```

**Свободное время.** Стенд не хранит расписание и не проверяет занятость, поэтому ассистент считает
слоты сам: «Свободен» в Excel кейса минус записи команды на стенде, минус время ближе 30 минут,
минус отпуска и больничные врача. Горизонт записи — 14 дней.

**Исходящие напоминания.** За рабочий день до приёма (приёмы в понедельник — в пятницу) ассистент
звонит, называет только имя и отчество, проверяет, что ответил нужный человек, и получает
подтверждение. Если пациент не может прийти, ассистент сразу предлагает другое время, при отказе
отменяет запись, и освободившийся слот достаётся другому пациенту.

## Ожидаемый эффект

Оценки по данным кейса, средний приём по ОМС — 1 200 ₽.

- **Неявки.** Сейчас 26 неявок в день ≈ 31,8 тыс. ₽ простоя. Снижение на 30–40% за счёт напоминаний
  с переносом — 9,5–12,7 тыс. ₽ в день, 2,4–3,2 млн ₽ в год (≈ 250 рабочих дней).
- **Пропущенные звонки.** Ассистент отвечает сразу и параллельно на любое число звонков, в том числе
  до 8:00 и после 20:00. Остаются только переводы на сотрудника, которые ждут в очереди.
- **Время регистраторов.** 89% звонков типовые; при доле автоматизации 60% это около 116 звонков
  в день, то есть 4 часа разговоров, которые уходят от регистратора к очному обслуживанию.

## Внедрение

1. **Пилот:** запись на приём и напоминания (сценарии С-01, С-10), ассистент работает только в часы пик
   и вне часов работы операторов.
2. **Расширение:** перенос, отмена, справки, вызов на дом в полуавтоматическом режиме.
3. **Контур заказчика:** локальная LLM за тем же Anthropic-совместимым API вместо облачного шлюза,
   интеграция с телефонией через Asterisk, речевая аналитика на обезличенных стенограммах.

## Стек

Python 3.12, асинхронное ядро на asyncio, httpx (клиент стенда), SQLite (данные на нашей
стороне), Anthropic SDK + ClaudeHub (Claude, запасной разбор реплик). Голос — GigaAM / faster-whisper
(STT) и Silero (TTS), локально.
