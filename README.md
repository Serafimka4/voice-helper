# Голосовой ассистент регистратуры поликлиники

Хакатон «Точка сборки», кейс DBI «В часы пик не дозвониться».

Ассистент принимает звонки пациентов вместе с регистраторами: записывает к врачу, переносит
и отменяет записи, отвечает на справочные вопросы и накануне приёма обзванивает пациентов
с напоминанием. Жалобы, медицинские вопросы, острые состояния и всё нестандартное он сразу
переводит на сотрудника, передавая карточку с сутью обращения. Каждое действие фиксируется
в МИС (стенд «Регистратура»).

**Основная идея и цифры — в [docs/IDEA.md](docs/IDEA.md).**

Здесь собрано ядро ассистента: понимание реплик, сценарии разговора, работа со стендом,
подбор свободного времени и перевод на оператора. Голосовой слой (телефония, STT, TTS)
подключается поверх через `DialogManager.handle(state, текст) → Reply`.

Сценарии и формулировки взяты из регламента поликлиники `data/case/reglament.docx` (РГ-ТЕЛ-01):
каталог интентов, словарь синонимов, красные флаги, матрица маршрутизации R-01…R-16,
коды результата и контрольные диалоги из Приложения Д покрыты тестами.

## Быстрый старт

```bash
uv sync
cp .env.example .env          # вписать REGISTRY_TOKEN; без токена работает фейковый стенд
uv run pytest                 # 81 тест
uv run python -m voice_helper.cli --fake --now "15.10.2026 11:00"
```

## Архитектура

```
реплика ─► nlu.Utterance (числа словами → цифры, ё→е)
            │
            ├─► guard.check_red_flags  — на КАЖДОЙ реплике: R-01 (103/112), R-09, R-11
            ├─► guard.check_routing    — оператор, жалоба, «вы робот?», платное, R-12…R-16
            ├─► медицинский вопрос     — граничная фраза, при настаивании R-04
            └─► DialogManager._on_<шаг> — сценарии С-01…С-15
                   │   └ правила не поняли → llm.LLMInterpreter (Claude через ClaudeHub)
                   │     переписывает реплику в каноническую форму → снова правила
                   │
                   ├─ SlotService: свободно = «Свободен» в Excel − записи команды на стенде
                   │                − < 30 минут до приёма − недоступность врача; горизонт 14 дней
                   ├─ RegistryClient: /api/v1, лимит 10/мин, повтор по 429 Retry-After, пагинация,
                   │                кэш врачей
                   ├─ KnowledgeBase: FAQ раздела 6 и прайс
                   └─ Storage (SQLite, в контуре): телефоны, журнал звонков с кодами результата,
                                    статусы напоминаний, карточки перевода, лист ожидания
```

| Модуль | Что делает |
|---|---|
| `registry.py` | HTTP-клиент стенда и протокол `Registry` |
| `fake_registry.py` | Стенд в памяти с теми же правилами (409, 400 на деактивированного врача, идемпотентные клиенты) |
| `schedule.py` | Импорт Excel кейса в `data/schedule.json` (85 врачей, ~43 тыс. свободных слотов) |
| `slots.py` | Подбор времени с учётом пожеланий: день, «после обеда», «не в пятницу», «на следующей неделе», «попозже» |
| `nlu.py` | Интенты, специальности и синонимы, даты и время, ФИО, даты рождения («двенадцатое марта семьдесят восьмого») |
| `numbers.py` | Числа словами в обе стороны, даты и время для синтеза речи («в девять тридцать») |
| `guard.py` | Красные флаги категорий А и Б, маршрутизация R-01…R-16, граничные фразы |
| `dialog.py` | Сценарии разговора, карточка перевода, `POST /escalations` |
| `llm.py` | Claude через ClaudeHub: запасной разбор непонятых реплик, маскирование ПДн |
| `reminders.py` | Отбор записей для обзвона: за рабочий день до приёма, без свежих записей, без отказавшихся |

## LLM: Claude через ClaudeHub

[ClaudeHub](https://app.claudehub.fun/docs) — Anthropic-совместимый шлюз, поэтому используется
официальный SDK `anthropic` с `base_url=https://api.claudehub.fun`. Модель по умолчанию —
`claude-opus-5-5` с `effort: low` (меняется через `LLM_MODEL`). Чтобы включить, впишите ключ
`sk-hub-...` в `CLAUDEHUB_API_KEY` в `.env`. Без ключа ассистент работает только на правилах.

Роль модели узкая: она вызывается, только когда правила не поняли реплику, и возвращает
каноническую фразу («тот, что попозже» → «последний»), которую снова разбирают правила.
Модель не говорит с пациентом и не действует в МИС; красные флаги проверяются до неё.
Таймаут — 8 секунд без повторов: если ClaudeHub не ответил, ассистент просто переспрашивает.

**152-ФЗ.** ClaudeHub — внешний облачный сервис. Поэтому реплики с шагов идентификации, адреса
и описания состояния в модель не отправляются, а телефоны и полные даты маскируются. На стенде
все данные вымышленные. В контуре заказчика ClaudeHub заменяется локальной моделью за тем же
Anthropic-совместимым API — меняется только `CLAUDEHUB_BASE_URL`.

## Ограничения и открытые вопросы

- **`/escalations` требует `client_id`.** Перевод до идентификации (просьба «соедините»,
  экстренный случай в первой фразе) фиксируется только локальной карточкой: регламент запрещает
  задерживать перевод ради ФИО. Если пациент уже назвал ФИО и дату рождения, карточка клиента
  заводится и заявка уходит на стенд.
- **Направлений на стенде нет**, поэтому для специалистов по направлению ассистент верит ответу
  пациента «да, есть». В боевой МИС здесь проверка направления.
- **Готовность анализов**: на стенде нет данных, поэтому ассистент отвечает сроками и способами получения.
- **«Записан» в Excel** — это вымышленные пациенты, такие слоты считаются занятыми. Excel заканчивается 31.12.2026.
  Перед демо переимпортируйте расписание с актуальной даты:
  `uv run python -m voice_helper.schedule data/case/schedule.xlsx data/schedule.json`.
- **Стенд отвечает на неверный токен с задержкой около 11 секунд**, поэтому таймаут клиента — 15 секунд.
- Напоминания запрашивают `GET /clients/{id}` на каждую запись. При лимите 10 запросов в минуту
  обзвон стоит растянуть или кэшировать клиентов.
